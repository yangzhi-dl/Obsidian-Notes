# 代码阅读与学习方法论

> 来自某处总结的宝贵经验，记录在此。

---

## 1. 代码阅读技巧

- **不要从头读到尾**。先看模块的 `pom.xml` 了解依赖，再看 Controller 了解对外接口，然后深入 Service 实现。
- **Git blame 是最好的老师**。看到不懂的代码，用 `git log --follow -p <file>` 看它是谁写的、什么时候加的、commit message 写了什么。
- **画图比看代码更重要**。时序图、架构图、数据流图——画出来的过程就是理解的过程。

## 2. 提问的艺术

- **错误的提问**："这个项目怎么跑不起来？"
- **正确的提问**："我在启动项目时遇到了 `Connection refused: Milvus` 的错误，我已经检查了 Milvus 的 Docker 容器状态是 running，端口 19530 也正常，但应用还是连不上。我怀疑是配置中的 host 不对，你能帮我看一下吗？"
- **原则**：描述你做了什么、你期望什么、实际发生了什么、你已经排除了什么。

## 3. 不仅要会用，还要会讲

- 每个你学懂的模块，试着录一个 5 分钟的讲解视频（或写一篇文档）。
- 费曼学习法：如果你不能向一个完全不懂的人解释清楚，说明你自己还没真正理解。
- 团队分享是技术成长最快的方式——主动争取做技术分享的机会。

## 4. 尽早建立"问题雷达"

- 读代码时记录你觉得"奇怪"的地方
- 运行时记录你遇到的错误和解决方案
- 定期和 Leader 讨论你的发现
- 这些积累会成为你"踩坑经验"的来源

## 5. 心态建设

- 这个项目 687 个 Java 文件，你看不完也记不住——**不需要**。关键是学会"按需阅读"：你需要改什么功能，就读什么代码。
- 前两周你大概率啥也做不了——**这很正常**。把重点放在理解"数据是怎么流转的"。
- 遇到不会的技术栈（MyBatis-Plus、Sa-Token、Spring AI、Milvus……），**不要试图全部学透再动手**。先会用（看官方 Quick Start），再理解原理（看源码），最后能改进（贡献 PR）。
