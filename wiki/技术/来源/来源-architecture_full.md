# 来源：需求从0到1落地全流程（架构师视角）

> 本文档从架构师的视角，完整梳理一个需求从提出到上线复盘的全生命周期，每个阶段给出具体的动作、产出物、常见坑点和检查清单，可作为团队研发规范或个人 Checklist 使用。

## 核心要点

### 9 阶段生命周期

| 阶段 | 核心动作 | 输出物 |
|------|----------|--------|
| 需求接收与澄清 | 追问5个关键问题，明确 MVP 边界 | 《需求澄清纪要》 |
| 需求分析 | IPO 模型 + 场景拆分（正常/异常/边界） | 场景拆分表 |
| 技术方案设计 | 架构/表/API/缓存/异步设计 | 《技术方案设计文档》 |
| 技术评审 | 检查 N+1、事务、性能、扩展性等 | 评审意见 |
| 开发 | DB→DAO→Service→Controller 分层实现 | 自测通过的代码 |
| 测试 | 单测→接口测试→压测 | 测试报告 |
| 上线 | 灰度发布 + 回滚方案 | 上线确认 |
| 监控 | 流量/性能/稳定性/数据库/资源 5 维度 | 告警配置 |
| 复盘 | 性能/架构/代码三维度沉淀 | 《项目复盘报告》 |

### 核心哲学

> **每个阶段都要有明确的输出物，且前一阶段的产出是后一阶段的输入**——避免"文档是文档，代码是代码"的两张皮问题。

### 关键产出物链

```
场景拆分表 → 测试用例（直接复用）
技术方案设计文档 → 评审输入
回滚脚本 → 上线安全兜底
复盘报告 → 团队经验沉淀
```
