# 代码阅读方法论

> 读代码 ≠ 从头读到尾。**带着问题读，带着工具读，带着脑子读。**

---

## 阅读顺序

不要从头读到尾，而是"倒着读"：

```
1. pom.xml / package.json    → 了解依赖栈
2. Controller / API 层        → 了解对外接口
3. Service 层                 → 了解业务逻辑
4. 数据层 (DAO/Repository)    → 了解数据模型
```

## 核心技巧

### Git blame 是最好的老师
看到不懂的代码，用 git 追溯它的历史：

```bash
git log --follow -p <file>
git blame <file>
```

看它是谁写的、什么时候加的、commit message 写了什么——往往比文档更真实。

### 画图比读代码更重要
- 时序图 → 理解调用链路
- 架构图 → 理解模块关系
- 数据流图 → 理解数据流转

**画出来的过程就是理解的过程。**
