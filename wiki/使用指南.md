# 📖 ObNotes 使用指南

> 一句话概括：**收集 → 整理 → 应用 → 输出 → 归档，让知识库自生长。**

---

## 1. 快速记录

临时内容进入 inbox。

```
inbox/今天看到的一篇美联储文章.md
```

允许内容不完整，每周至少清理一次。

**怎么存？**
- 网页文章 → Obsidian Web Clipper 剪藏到 `raw/对应领域/文章/`
- 随手想法 → 在 Obsidian 里直接新建 `raw/对应领域/随记/YYYY-MM-DD-标题.md`
- 不确定归属 → 丢 `inbox/`，每周清理
- 手机端快速记录 → 用 Obsidian 移动端同步到 inbox

---

## 2. 保存原始资料

确认来源后进入 raw，按领域存放。

```
raw/投资/《投资最重要的事》第二章.md
raw/技术/文章/微服务架构设计.md
raw/工具/随记/Obsidian插件推荐.md
```

尽量保留原始信息，记录来源。

---

## 3. 生成结构化知识

从原始资料中提取知识到 wiki：

```
wiki/投资/概念/第二层思维.md
wiki/投资/概念/风险控制.md
wiki/投资/综合/如何避免追涨杀跌.md
```

AI 生成的内容默认 status: seed，需要人工确认后升级。

---

## 4. 应用于项目

项目不复制 wiki 正文，使用双链引用：

```
projects/投资入门/资产配置分析.md
```

引用格式：[[资产配置]]、[[标普500]]

---

## 5. 形成输出

成熟内容进入 outputs：

```
outputs/文章/
outputs/报告/
outputs/分享稿/
outputs/视频脚本/
```

---

## 6. 日常使用流程

### 🗓️ 每日（5 分钟）

1. **遇到好东西 → 存 raw**。看到文章、视频、想法，判断领域后丢进对应 `raw/`。
2. **跟 AI 说「整理一下」**。AI 自动读取新文件、创建来源摘要、提取核心概念、更新索引。
3. **想查东西 → 「查一下 xxx」**。AI 优先从 wiki 检索答案，引用来源。

### 📅 每周（15 分钟）

1. **清理 inbox**。把未分类内容移到对应 raw 领域，或直接丢弃。
2. **检查 seed 笔记**。AI 创建的笔记默认 `status: seed`，需要你人工阅读后升级：
   - `seed → reviewed`（内容正确，可以信赖）
   - `seed → deprecated`（内容过时或错误）
3. **补充双链**。检查新笔记是否缺少关联。例如在 `wiki/投资/概念/` 下写了"资产配置"，可以链接到已有的"标普500"和"纳斯达克100"。
4. **更新项目状态**。在 `projects/` 中同步当前进展。

### 📆 每月（30 分钟）

1. **归档完成的项目**。`projects/` 中完成的项目移动到 `archive/projects/`。
2. **健康检查**。说「检查健康度」，AI 检查孤儿页面、断链、概念重复、索引覆盖率。
3. **检查待验证内容**。搜索带有"待验证"标记的笔记，集中确认信息。
4. **更新知识地图**。确保 `wiki/index.md` 覆盖所有活跃内容。
5. **检查缺少来源的结论**。追查缺少来源的知识点。

## 7. 场景化使用示例

### 📚 场景：你在读一本投资书

**步骤 1**：在 `raw/投资/` 下建笔记
```
raw/投资/《投资最重要的事》- 第二章.md
```
记录书中原文、你的疑问、初步理解。

**步骤 2**：说「整理一下」
AI 提取出概念：
```
wiki/投资/来源/《投资最重要的事》.md     ← 全书摘要
wiki/投资/概念/第二层思维.md               ← 核心概念
wiki/投资/概念/风险控制.md                 ← 核心概念
```

**步骤 3**：你读 AI 生成的笔记，修正错误，把 `status: seed` 改为 `reviewed`。

**步骤 4**：写一篇综合笔记：
```
wiki/投资/综合/当前市场环境下的风险控制.md
```

### 🛠️ 场景：你在做一个项目

**步骤 1**：在 `projects/` 下建项目目录
```
projects/博客站搭建/
├── index.md         ← 目标、范围、状态
├── tasks.md         ← 任务列表
└── decisions.md     ← 架构决策
```

**步骤 2**：项目中引用 wiki 知识，不复制正文
```markdown
参考 [[wiki/技术/概念/静态站点生成器|静态站点生成器]] 的技术选型分析。
本项目选择 Astro 作为框架。
```

**步骤 3**：完成后移到 `archive/projects/博客站搭建/`

### ✍️ 场景：你要写一篇文章

**步骤 1**：在 `outputs/文章/` 里写草稿。
**步骤 2**：引用 `wiki/` 中的来源和概念作为论据。
**步骤 3**：用 [[templates/输出模板|输出模板]] 里的发布检查清单核对：
- 事实已经核对
- 时间敏感信息注明日期
- 引用来源完整
- 链接有效
- 不包含未经确认的 AI 推测
- 已完成最终校对

**步骤 4**：发布后把链接记录回 wiki 对应笔记的 source 字段。

### 💡 场景：你在学一个新领域

**步骤 1**：如果不存在对应领域目录，在 `raw/` 和 `wiki/` 下新建领域目录（参考已有的「投资」「技术」等结构）。
**步骤 2**：在对应 `raw/` 下开始收集资料。
**步骤 3**：每次积累 2-3 篇资料后说「整理一下」。
**步骤 4**：知识积累到约 20-30 篇笔记后，再考虑在该领域下增加子目录。

## 8. AI 协作分工

| AI 擅长 | 你需要做 |
|---------|---------|
| 快速从 raw 提取概念草稿 | 确认内容是否准确 |
| 建立双链和索引 | 补充个人理解和判断 |
| 发现知识关联 | 决定哪些知识真正重要 |
| 生成复习题 | 形成自己的观点和结论 |
| 标记过时内容 | 删除或归档的决定 |
| 定期健康检查 | 新领域的添加和调整 |

**黄金规则**：AI 生成的内容默认 `status: seed`，意味着"可能是对的，但还没确认"。在你读过、修正过之前，别把它当最终真理。

## 9. AI 触发指令速查

| 你说 | AI 做什么 |
|------|----------|
| 「记一下 [内容]」 | 碎片录入 → `raw/随记/` |
| 「整理一下」 | 扫描 raw 新文件 → 创建来源/概念/实体 → 更新索引 |
| 「查一下 [关键词]」 | 从 wiki 检索知识 → 综合回答 → 引用来源 |
| 「把这段沉淀到 wiki」 | 当前问答/分析回写到 `wiki/综合/` |
| 「检查健康度」 | 检查孤儿页、断链、重复概念、过期内容 |

## 10. 完整目录说明

| 目录              | 谁维护    | 用途      |
| --------------- | ------ | ------- |
| `inbox/`        | 用户+AI  | 临时收集    |
| `diary/`        | 用户     | 日记与复盘   |
| `raw/{领域}/`     | 用户     | 各领域原始资料 |
| `wiki/{领域}/来源/` | **AI** | 来源摘要    |
| `wiki/{领域}/概念/` | **AI** | 核心概念    |
| `wiki/{领域}/实体/` | **AI** | 实体信息    |
| `wiki/{领域}/综合/` | **AI** | 综合分析    |
| `projects/`     | 用户+AI  | 项目文件    |
| `outputs/`      | 用户+AI  | 输出成果    |
| `templates/`    | 用户+AI  | 模板      |
| `archive/`      | AI     | 归档      |

## 11. 快速上手

```
第 1 步：看到好文章 → 存到 raw/对应领域/
第 2 步：说「整理一下」→ AI 编译成 wiki 概念
第 3 步：说「查一下 xxx」→ 从 wiki 中检索知识
第 4 步：每天写日记 → diary/YYYY-MM-DD.md
第 5 步：做项目 → projects/ 中使用知识
第 6 步：成品 → outputs/ 准备发布
```

**一句话总结每天的节奏：**
```
丢 raw → 说"整理一下" → 每周看 seed → 每月健康检查
```

## 12. 不推荐的做法

- ❌ 所有东西都扔进通用
- ❌ AI 一次生成几百篇空洞笔记
- ❌ 只做摘要，不形成自己的理解
- ❌ 创建大量没有正文的双链
- ❌ 同一个概念重复创建多篇笔记
- ❌ 不记录来源
- ❌ 直接删除过时知识
- ❌ 把项目过程全部塞进 wiki
- ❌ 把原始摘录直接当作成熟知识
- ❌ 追求笔记数量而非质量
- ❌ 追求目录结构完美而迟迟不开始记录

## 13. Dataview 动态查询（可选）

> 以下查询需要安装 Dataview 插件，不安装不影响知识库其他功能。

### 查找所有 seed 笔记（等待人工确认）
```dataview
TABLE file.folder AS "位置", created AS "创建时间"
FROM "wiki"
WHERE status = "seed"
SORT created ASC
```

### 最近更新的笔记
```dataview
TABLE tags, created, updated AS "最近更新"
FROM "wiki"
SORT updated DESC
LIMIT 20
```

### 按领域统计
```dataview
TABLE length(rows) AS "笔记数"
FROM "wiki"
GROUP BY domain
SORT length(rows) DESC
```

## 14. 高阶技巧

### Git 版本管理
```bash
cd ObNotes
git status              # 查看改了什么
git diff                # 查看具体变更
git diff --stat         # 查看变更文件统计
git commit -am "更新了xxx"   # 手动提交
```

### 图谱视图
在 Obsidian 中打开 Graph View（左侧工具栏），直观看到知识之间的连接网络。

### 配合日记使用
每天写日记是投喂知识库最好的方式：
- 在 diary/ 中记录学到的内容
- 定期说「整理一下」把日记中的知识提炼到 wiki

### 手机端快速收集
- 安装 Obsidian 移动端
- 同步整个库
- 随手记到 inbox/，回家后再整理

### 知识增长节奏建议
- 不要一次性塞大量资料，AI 处理质量会下降
- 每次丢 2-3 篇新资料，说「整理一下」，确认后再继续
- 知识库是"长"出来的，不是"建"出来的
